# 角色工作台

## 文档范围

角色工作台用于创建、维护、预览和复用角色提示词原型。

角色负责定义稳定身份、判断方式、表达风格和行为约束。它不负责保存专业资料、当前任务、工具权限或长期记忆。

![角色提示词工程工作台](/images/roles/role-workbench.webp)

## 核心对象

| 对象 | 说明 |
| --- | --- |
| Role | 一份可复用角色定义 |
| Role Fields | 按职责拆分的提示词字段 |
| Generation Parameters | 温度、Top P、Top K 等生成参数 |
| Preview | 查看字段如何拼装进请求上下文 |
| Role Copy / Import | 从已有定义创建独立副本 |

## 角色与其他上下文

| 内容 | 应归属的位置 |
| --- | --- |
| 身份、关系姿态、表达方式 | 角色 |
| 专业资料和事实来源 | 知识库 |
| 当前聊天记录 | Thread / Message |
| 当前任务要求 | 用户输入或任务上下文 |
| 跨线程用户事实 | 记忆系统（当前不等于角色） |
| 可使用的外部能力 | Tool / MCP |
| 工具审批规则 | Policy / Permission |
| 领域执行说明 | Skill |

把这些内容全部写入角色会导致 Prompt 过长、事实过期和权限边界不清。

## 角色字段

### 名称

用于列表识别。名称应简短、稳定，不包含一次性任务。

### 简介

用一至两句话说明用途。简介主要用于列表展示，不承担完整 Prompt 功能。

### 角色描述

定义身份、背景、职业、关系和稳定事实。

推荐包含：

```text
身份：……
背景：……
与用户的稳定关系：……
```

### 世界观

定义角色如何判断事实、风险和冲突。

```text
相信什么：……
如何核实事实：……
冲突时优先保护什么：……
```

### 人格核心

定义稳定气质、立场和行为方式。

```text
角色身份：……
对用户的态度：……
稳定行为：……
```

### 适用场景

定义角色通常工作的环境和目标边界。

```text
环境：……
关系：……
目标：……
风险或限制：……
```

### 示例对话

使用真实对话格式示范典型回应、澄清、拒绝或推进方式。

```text
{{user}}: 这个方案能上线吗？
{{char}}: 能，但要先补齐异常路径和回滚方案。
```

示例应少而准确，不要把行为说明伪装成对话。

### 表达风格

控制句长、语气、结构、术语和信息密度。

示例：

```text
先给结论，再说明依据。
语气平静直接，不使用夸张承诺。
必要时使用列表，避免重复同一结论。
```

### 约束规则

定义必须、禁止和冲突优先级。

```text
必须：……
禁止：……
冲突时优先：……
```

规则应可判断，避免“尽量”“看情况”等无法验证的表述。

## 生成参数

角色可以保存模型生成参数，例如：

- Temperature；
- Top P；
- Top K；
- 其他当前模型支持的参数。

生成参数影响采样行为，不替代角色字段。降低温度不能自动形成可靠身份，提高温度也不能补充缺失的事实和规则。

## 提示词预览

预览用于检查角色字段在请求中的位置：

```text
System Rules
→ Role Context
→ Optional Skill Context
→ Optional Knowledge Context
→ Thread History
→ Current User Input
```

预览应区分：

- 普通聊天；
- RAG 聊天；
- 角色字段；
- 知识上下文；
- 历史消息；
- 当前测试输入。

预览结果只是上下文构造检查，不代表模型最终输出一定符合角色定义。

## 列表与编辑操作

当前工作台支持或预留以下操作：

- 新建角色；
- 编辑名称、简介和字段；
- 保存生成参数；
- 预览拼装结果；
- 创建副本；
- 导入已有角色；
- 删除角色；
- 恢复到最近保存状态。

具体状态字段和导入格式以当前版本 UI 和 API 为准。

## 编写建议

- 把稳定身份和临时任务分开；
- 使用可观察行为替代形容词堆叠；
- 示例对话只覆盖高价值典型场景；
- 约束写明冲突优先级；
- 删除字段间重复内容；
- 专业事实放入知识库；
- 工具权限留在 Policy 和 Harness；
- 修改后使用预览检查最终上下文。

## 当前边界

角色工作台当前不等于：

- 长期记忆系统；
- 知识库；
- Tool 或 MCP 权限配置；
- Skill Runtime；
- 每个线程的动态关系状态机；
- 保证模型严格服从的确定性执行器。

模型仍可能受 System、用户输入、知识上下文、历史消息和 Provider 能力影响。

## 验证清单

1. 角色字段是否各自承担单一职责；
2. Prompt 预览是否包含预期内容；
3. 临时任务是否误写入角色；
4. 专业事实是否有来源；
5. 约束是否可判断；
6. 不同模型下的表现是否经过实际测试；
7. 导入和复制后是否形成独立对象。
