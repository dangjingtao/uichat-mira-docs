# 知识库与评测

## 文档范围

本页说明正式知识库的创建、文件处理、检索验证和评测流程。

知识库负责回答：

> 系统可以依据哪些资料进行检索和生成？

它不负责定义角色身份、长期记忆、工具权限或当前任务目标。

## 前置条件

上传和索引文件前，需要配置可用的默认 Embedding 模型。

```text
Provider Connection
→ Embedding Model
→ Default Embedding Binding
→ Knowledge Ingest Available
```

聊天模型和 Embedding 模型用途不同。配置聊天模型不代表知识库已经具备向量索引能力。

## 数据对象

| 对象 | 说明 |
| --- | --- |
| Knowledge Base | 一组具有共同主题和用途的资料集合 |
| Document | 已上传并处理的源文件 |
| Chunk | 文档经过解析和切分后的检索单元 |
| Embedding | Chunk 的向量表示 |
| Retrieval Result | 一次查询召回的 Chunk 与分数 |
| Evaluation Dataset | 固定问题、预期来源或参考答案 |
| Evaluation Run | 一次可复现的检索或生成评测 |

## 创建知识库

知识库可以保存以下元信息：

| 字段 | 用途 |
| --- | --- |
| 名称 | 唯一识别当前知识库 |
| 描述 | 说明资料范围和使用目的 |
| 人格 | 标记适合配合的专业身份 |
| 场景 | 标记典型业务场景 |
| 标签 | 分类和筛选 |

“人格”和“场景”只是资料元信息，不等于角色卡，也不会替代系统 Prompt。

## 文件上传流程

```text
Select Files
→ Parse
→ Configure Chunking and Cleaning
→ Preview Chunks
→ Generate Embeddings
→ Persist Document and Index
→ Verify Result
```

![设置文本分段与清洗参数](/images/knowledge-base/kb-upload-chunking.webp)

*上传流程中可以配置切块、重叠、语言和清洗规则，并预览实际分段。*

![知识文档处理完成](/images/knowledge-base/kb-upload-complete.webp)

*处理完成后应确认文件数、Chunk 数和索引状态。*

## 分段与清洗

当前上传流程可以配置：

- 切块方式；
- 最大长度和重叠长度；
- 长度单位；
- 是否保留分隔符；
- 语言预设；
- 自定义分隔符；
- 连续空白、URL、邮箱等清洗规则；
- 是否按问答结构分段。

预览区应至少显示：

- 抽样 Chunk；
- Chunk 总数；
- 平均长度；
- 最短和最长长度；
- 文本清洗后的实际内容。

分段参数应在正式入库前验证。错误切分会直接影响检索和后续回答质量。

## 文档管理

![知识库文档列表](/images/knowledge-base/kb-list-overview.webp)

文档列表用于：

- 搜索和切换知识库；
- 查看文档状态、更新时间和 Chunk 数；
- 启用或停用单个文档；
- 添加或删除文件；
- 编辑知识库元信息；
- 删除整个知识库。

删除文档时，与该文档关联的 Chunk 和索引数据也会被移除。删除操作不可撤销。

## 文档详情

![知识库文档详情与分段预览](/images/knowledge-base/kb-document-detail.webp)

文档详情应提供：

- Document ID；
- 来源和文件类型；
- 创建和更新时间；
- 标签；
- 字符数和 Chunk 数；
- 原始文件大小；
- 索引状态；
- 内容摘要；
- 真实 Chunk 预览。

检查重点：

- 文件是否正确解析；
- 标题、段落和列表是否被错误截断；
- Chunk 是否过长或过短；
- 页眉、页脚和乱码是否进入索引；
- 关键语义是否保持完整。

## 检索测试

文件成功入库不等于检索质量合格。

检索测试用于输入真实问题并检查：

- 命中了哪些文档；
- 返回了哪些 Chunk；
- 排序是否合理；
- 相关内容是否被遗漏；
- 错误段落是否占据前列。

测试问题应接近用户真实提问，不要只输入文件标题。

```text
不推荐：产后康复指南
推荐：剖宫产后多久可以开始低强度核心训练？
```

## 评测模式

| 模式 | 目标 |
| --- | --- |
| 仅检索 | 验证正确资料是否被召回和排序 |
| 检索 + 生成 | 同时验证回答是否依据来源、切题和覆盖关键点 |

常用指标：

| 指标 | 说明 |
| --- | --- |
| Hit@K | 前 K 个结果是否包含正确内容 |
| Recall@K | 正确内容被召回的覆盖程度 |
| MRR | 正确结果的排序位置 |
| Faithfulness | 回答是否忠于来源 |
| Relevance | 回答是否切题 |
| Completeness | 关键点是否覆盖完整 |
| Source Hit | 是否命中预期来源 |
| Avg Latency | 平均运行耗时 |

评测结果用于定位问题，不用于证明所有真实场景都已通过。

## 重建索引

以下情况需要评估重建索引：

- 更换 Embedding 模型；
- Embedding 维度变化；
- 修改分段或清洗策略；
- 文档内容更新；
- 索引损坏或状态异常。

重建前应确认当前模型和分段配置。重建可能改变现有检索结果。

## 正式知识库与 Markdown 工作空间

| 维度 | 正式知识库 | Markdown 工作空间 |
| --- | --- | --- |
| 入库 | 需要 | 不需要 |
| 分段与 Embedding | 需要 | 不需要 |
| 向量检索 | 支持 | 不依赖 |
| RAG 与评测 | 支持 | 不是主要目标 |
| 适用场景 | 长期资料、跨文件检索 | 轻量浏览、定位、整理项目文档 |

两条路径可以服务相似任务，但不是同一 Runtime。

## 当前边界

- 知识库命中不等于最终专业结论正确；
- 高风险领域仍需人工判断；
- 评测分数不代表生产环境绝对可靠；
- 资料质量、解析、分段、Embedding、检索、Rerank 和生成都可能成为问题来源；
- 没有默认 Embedding 时，不应伪装为可以正常入库；
- 删除和重建操作需要明确提示影响。

## 验证清单

1. 默认 Embedding 是否可用；
2. 文件解析和 Chunk 预览是否正确；
3. 索引状态是否完成；
4. 真实问题能否召回正确来源；
5. RAG 回答是否引用实际检索内容；
6. 评测结果是否可复现；
7. 删除和重建后状态是否一致。
